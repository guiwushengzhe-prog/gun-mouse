# 嘉立创命令行长参数修复

原包装器虽然支持 `--code-file`、`--args-file`，但读完后又把全文塞入 Windows 命令行，因此仍会触发约 32KB 的进程启动长度限制。

现在保留原调用方式。`--transport auto` 为默认：短调用仍直接传入；按 Windows 引号规则计算后超过 30,000 个 UTF-16 字符的调用，将代码和参数写到本工作树 `.logs/eda-cli-payload/`，命令行只传一个短引导程序，由官方 `eda.sys_FileSystem.readFileFromFileSystem` 读取后执行。`--transport file` 可强制文件传输；`--transport inline` 可强制原方式，过长时在启动前明确报错。

载荷保留在忽略目录中，以便查看超时调用。返回证据继续保留原来的 `ok`、`value` 等字段，并添加 `_local_transport`：传输方式、实际命令长度、载荷路径、字节数和 SHA-256（内容校验值）。无源码的注册函数调用不能由此引导执行，长参数仍需分批或改用源码调用；包装器会明确报错。

官方文档将文件 API 的访问范围描述为配置的项目目录及其子目录，并要求外部交互权限；本次客户端行为见下方现场结果。此修复不改变软件权限或项目目录配置；如实际文件读取受限，会保留官方错误。脚本只负责传输，不解决自动布线、覆铜计算或原理图网表读取卡住的问题。

## 本次现场结果

2026-10-05，主代理在收尾副本自己的会话中执行只读验证。嘉立创专业版 4.1.66 返回验证值及 `paddingLength=64000`：原方式命令需 64,329 个 UTF-16 字符，文件引导实际只需 602 个字符，载荷字节数 64,252。结果保存于 `.logs/transport-probe-result.json`，本次测试确认长参数已经通过官方文件读取及异步函数执行完整送达，没有修改电路。

同一会话的 `getProjectsPaths()` 返回空数组，但使用既有 `--ext-uuid eda` 仍成功读取本工作树的载荷。这是本次客户端行为，不能仅凭空数组推定文件不可读，也不能据此推定其他路径、权限配置或版本均可读取。此次没有扩大目录权限或更改全局设置；迁移环境时可先运行上述只读探针。

六项纯本地传输检查也已通过，覆盖长源码、长参数、中文、补充平面字符、空参数、重复选项以及强制内联的超长预检。此证据只涉及命令行传输，不表示电路规则检查、覆铜或自动布线已完成。

## 验证

纯本地传输检查，不启动嘉立创、不打开设计：

```powershell
$env:PYTHONUTF8 = '1'
& 'E:\GunMouseCAD\Miniforge3\python.exe' scripts\test_eda_cli_transport.py
```

现场验证由主代理在它自己的新副本会话执行。先准备只读代码，内容只需：

```javascript
return { value: __CLI__.args.sample, version: eda.sys_Environment.getEditorCurrentVersion() };
```

再准备参数文件 `{"sample":"验证值"}`，强制走文件：

```powershell
& 'E:\GunMouseCAD\Miniforge3\python.exe' scripts\eda_cli.py `
  --transport file --code-file .logs\transport-probe.js `
  --args-file .logs\transport-probe-args.json `
  --evidence .logs\transport-probe-result.json `
  -- invoke --session 新副本会话编号 --ext-uuid eda --timeout 60000
```

在代码注释或参数字符串内增加超过 32KB 的内容，再用默认 `auto` 调用，可验证长内容仍从文件传输，返回值正确且 `_local_transport.command_line_utf16_units` 小于上限。此验证只查询版本和参数，不更改电路或会话。

本地官方接口资料：`.logs/cli-for-ai.md` 的“Project Storage Directory”“Writing Files”章节，以及 `doc api SYS_FileSystem readFileFromFileSystem` 返回的接口说明。
