# 2026-10-05 嘉立创原生接口试验结果

覆铜已能通过程序接口自动创建、计算和保存。自动布线算法也能由程序启动，但专用接口仍有接收端缺口；已在四焊盘小板上完成“菜单启动原生算法 → 读取结果 → 重开自有测试会话 → 公共图元接口写回 → 保存 → 重开核对”的兼容流程。

当前使用嘉立创专业版 4.1.66，接口包为 `0.3.44.a22d1ca5`。全部试验位于分支 `codex/eda-recovery`，工作树为 `F:\项目\枪型飞鼠\.worktrees\eda-recovery`。原成果 `claude/pcb-shell-v1` 的 `dff2043` 和交付副本 `codex/pcb-shell-finish` 的 `2031276` 都保留，正式飞鼠板、器件位置、走线、外壳和制造文件未在此轮改动。

| 项目 | 实际结果 | 判断 |
| --- | --- | --- |
| 专用自动布线接口 | 正确字段 `RoutingNets`，等待 12 秒仍未返回，未新增路线 | 静态代码中缺少对应接收注册，原专用接口未修复；不能靠增加超时解决 |
| 菜单兼容入口 | 可见和无窗口会话均生成两条原生路线 | `sys_Window.openUI('autoRouting(ALL_NETS)')` 有效，但参数存在版本变化风险 |
| 默认迭代预览 | 画布有路线，保存返回 `false`，磁盘没有路线；创建覆铜也被拒绝 | 预览把工程设为只读，不能把画布计数当作完成 |
| 自动应用兼容流程 | 捕获原生路线，关闭自有测试会话并重开原板，公共直线接口写回；保存成功 | 两条同网连接写入磁盘；完整关闭重开后仍在，规则检查零错误 |
| 修正后的覆铜接口 | 显式闭合四角创建和重建成功，返回一个面及八条热焊连接线 | 新建空白工程也纯接口成功；不需要鼠标拖拽或快捷键 |
| 铜层导出 | 修正前顶层没有区域命令；修正后有一组 `G36/G37` 区域命令 | 铜面进入真实制板文件；压缩包完整性检查通过 |

覆铜测试最初有一处坐标错误。矩形编码 `['R',20,20,960,760,0,0]` 在原生 PCB 中从起点向负 Y 展开，实际范围为 Y=-740～20，未覆盖 Y=200 的地焊盘。删除孤岛后为空是合理结果，不能据此认定原生算法失效。最终使用 `[20,20,'L',980,20,980,780,20,780,20,20]`，四角均在 1000×800 密耳板框内。密耳是千分之一英寸；试验板尺寸为 25.4×20.32 毫米。

此前捕获的 `undefined.length` 异常发生在接口的空结果转换处；正确区域在可写状态下没有再出现该异常。此结果支持修正调用方式，也保留空结果处理缺陷的历史证据；不能推断原 AI 在复杂板上的所有历史异常都具有同一原因。

自动布线兼容适配 `apply_snapshot.js` 刻意只接受本次四焊盘、两条直线、零过孔、原板未布线的快照，并验证原焊盘编号、坐标和网络未改变。它没有自编算法重新规划路线。正式板的既有走线、过孔、圆弧和复杂网络尚未纳入该适配，不应直接在正式工程调用。官方文档将 `openUI` 标为不保证参数兼容的入口，软件升级后需要重新核对。

最终无窗口工程重新打开后：两组焊盘均有直接同网连接，读取到九条覆铜填充路径，设计规则检查返回空数组。填充路径保留接口原始编码，只用于确认实际结果；未用这些路径反推机械装配尺寸。制板文件 `headless-corrected-gerber.zip` 的 SHA-256 为 `3884337c97d30bbd280c4f6d5503e723486eedfa6d80dc911e0dc5d04ae0dfa4`。这些是软件和文件验证，适用范围为隔离小板。

重开的可见测试窗口已展示两条路线和真实地铜面。窗口对应 `pcb\eda-recovery-probe\eda-recovery-probe.eprj3`；无窗口持久化核对对应 `pcb\eda-recovery-probe-headless`；纯接口首次创建核对对应 `pcb\eda-recovery-probe-direct`。只关闭过本次自有测试会话，未停止公共后台或其他工程窗口。
