# 网表比较元数据问题定位

2026-10-05，仅在收尾副本读取导出文件和已安装软件代码，没有操作编辑器会话或修改工程。本说明解释为何引脚网络一致时，嘉立创专业版仍可能提示原理图与 PCB 网表不一致。

## 已确认的比较入口

本机客户端安装包中 `assets/pro-pcb/4.1.57.3c4dbafd/js/pcb.js` 的规则检查代码先请求原理图关联，再调用网表比较。实际比较由 `assets/pro-ui/4.1.68.3635b9da/js/ui.js` 的 `-compareNetList` 处理：分别解码电路板和原理图，使用 `G5e` 比较器比较器件，生成导入更新表；只要更新表仍有行，就返回差异并生成 `NetlistError`。这不只是引脚连通性比较。

阅读定位按字符偏移记录：`pcb.js` 约 8,327,000 为规则检查入口；`ui.js` 约 19,267,949 为网表比较处理，约 5,687,978 为解码器，约 5,711,901 为器件比较器。偏移仅适用于上述已安装资源版本，不是可调用接口；此次没有调用任何内部服务。

## 属性处理

解码器保留器件属性，只补充“转 PCB”为 `yes`、缺失或空的“加入器件清单”为 `yes`，并从本工程库刷新器件名与封装名。它没有删除或统一 `Channel ID`、`PCB Layer`、`Name`、`Value`。

普通属性比较忽略以下键：

```text
ID, Symbol, Convert to PCB, 3D Model, 3D Model Transform,
3D Model Title, FootprintName, DeviceName, SymbolName, Footprint,
CBB Title, CBB ID, Sim Model, image, Sim Model Title, Sim Model Path,
NGSpice Model, NGSpice Model Title, NGspice Model Path, Relevance
```

封装、器件及其名称另走替换比较，不能因其在上述列表中就断言完全不检查。“Reuse Block”和“Device”只在删除属性时视为固定字段；“IPC/DAC-2552”差异进入隐式修改分类。原值为 `={属性名}` 一类表达式时，还会用输入属性展开后比较；除此之外，字符串属性新增、删除或不同值都会产生修改项。引脚网络比较还会统一大写并检查引脚分类、差分对分类，另有替代器件库比较。

## 当前文件差异及最小修复方向

主代理恢复原理图器件名称、参数和采购属性后，读取当时最新的 `outputs/pcb-shell-v1/schematic-netlist.enet` 与 `deliverables/pcb-shell-v1/制板文件/gun-mouse-v1-网表.enet`，按上述属性规则离线核对，剩余差异为：

| 属性 | 差异数 | 电路板 | 原理图 |
|---|---:|---|---|
| 通道编号 `Channel ID` | 48 | 空 | 例如 `$1I49`，每个器件不同 |
| 放置层偏好 `PCB Layer` | 48 | `TopLayer` | 空 |

详细离线结果留在 `.logs/netlist-metadata-diff.json`。这是当时已导出文件的属性差异，不能代替修改后的现场规则检查。

最小修复方向是仅同步关联元数据：原理图将 `PCB Layer` 补为现有电路板的 `TopLayer`；电路板将每个器件 `Channel ID` 补为原理图已编译值。使用官方 `SCH_PrimitiveComponent.modify`、`PCB_PrimitiveComponent.modify` 的 `otherProperty` 参数，不提交坐标、旋转、实际层、封装、型号或焊盘网络修改。电路板代码中的通道编号直接取自组件属性映射，官方修改实现也写入该映射；先同步一个器件并重新导出确认，再扩展到其它器件，可核对实际保留效果。

同步后仍需要重新导出并现场运行 PCB 规则检查，确认报错清零，以及位置、走线、封装和网络保持原设计。此次研究没有执行元数据同步，也没有关闭规则来消除提示。

## 官方资料与证据边界

本地 `assets/pro-api/0.3.44.a22d1ca5/api-types.d.ts` 第 9,211 行与第 14,515 行分别定义电路板、原理图器件官方修改参数，包含 `otherProperty`。第 19,909 行定义 [官方普通网表比较接口](https://prodocs.easyeda.com/en/api/reference/pro-api.sys_tool.netlistcomparison.html)，返回网络或器件差异。普通网表比较与上述规则检查不是同一入口；不能仅凭其返回空数组推定规则检查清零。

本说明基于已安装版本的静态代码和副本导出文件，证明比较会检查上述元数据，也给出了符合官方修改接口的修复方向；最终是否清除提示以主代理的重新导出及现场规则检查为准。

## 后续实际解决证据

主代理随后使用官方接口把原理图 `PCB Layer` 补为 `TopLayer`，先同步电路板 R12 的通道编号并核对，再同步其余 47 个器件。主代理确认器件物理属性保持不变；本次修复只补关联元数据，没有重做电路、位置、走线、封装或型号，也没有关闭相关检查规则。

已读取现场规则检查证据 `outputs/pcb-shell-v1/eda-evidence/handoff-drc-final.json`：`ok=true`，`value.count=0`，`value.items=[]`，耗时约 7.1 秒。该证据证明新副本在检查时已无规则错误。主代理随后重新导出的 PCB 网表为 115,123 字节，交付记录以最终导出文件为准。

这个结果没有证明原生自动布线或覆铜计算问题已解决；这两项仍需要在独立实验副本验证。规则检查清零也不能代替实物装配、供电、触摸、无线或 USB 功能测试。
