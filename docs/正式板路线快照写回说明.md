两份脚本已在正式板独立副本实际执行。原板575段直线、95个过孔完整写回、保存并重开，网络及全部路线几何和属性一致，规则检查零错误。原生自动布线结果的500段路线写回时丢失3段极短线，该兼容案例没有通过；详见《正式PCB与外壳程序验证结果》。原工程和已有交付保留。

## 输入与调用

`snapshot_routes.js`只读取当前活动电路板。允许来源工程为`gun-mouse-formal-baseline`、`gun-mouse-formal-roundtrip`、`gun-mouse-formal-route`，并核对当前文档类型为PCB、PCB所在板子及当前文档均属于当前工程。不会自行切换文档。

原板快照参数可用`{"expectedCounts":{"components":48,"lines":575,"vias":95,"arcs":0,"polylines":0}}`。这是实际软件读到的数量；新布线不能照抄原板数量。数量不符即报错。接口坐标原值以密耳保存，不作毫米换算；1密耳等于0.0254毫米。

通过既有命令行包装器读取脚本、参数文件并留证据，建议显式使用文件传输以免超过Windows命令行长度上限：

```powershell
& 'E:\GunMouseCAD\Miniforge3\python.exe' scripts/eda_cli.py --transport file --code-file scripts/formal_validation/snapshot_routes.js --args-file .logs/formal-snapshot-args.json --evidence .logs/formal-route-snapshot.json --timeout-seconds 180 -- invoke --session '<会话编号>' --ext-uuid eda --timeout 120000
```

`apply_routes.js`只能写入`gun-mouse-formal-roundtrip`和`gun-mouse-formal-route`。可直接使用快照证据JSON作为参数（自动取`value`）；此时要求来源与目标工程、PCB编号一致。跨独立副本需构造以下参数，并绑定当前目标工程／PCB编号：

```json
{
  "snapshot": {"schema": "gun-mouse-routes-v1", "其他字段": "此处应放完整快照value，或完整证据对象"},
  "target": {"projectUuid": "目标工程编号", "boardUuid": "目标PCB编号"}
}
```

```powershell
& 'E:\GunMouseCAD\Miniforge3\python.exe' scripts/eda_cli.py --transport file --code-file scripts/formal_validation/apply_routes.js --args-file .logs/formal-apply-args.json --evidence .logs/formal-apply-result.json --timeout-seconds 180 -- invoke --session '<会话编号>' --ext-uuid eda --timeout 120000
```

脚本和包装器参数必须放在`-- invoke`之前。文档示意编号不是可直接运行的真实会话。

## 写回与拒绝条件

写入前逐字段核对全部元件、关联焊盘和独立焊盘，包括位置、旋转、封装、网络、焊盘形状、孔、阻焊扩展和锁定。字符串、布尔及结构严格相等；数值容许1e-6的接口换算误差。目标两铜层的直线、圆弧、折线以及全部过孔必须为空。脚本不删除任何已有图元。

所有路线参数先完成校验，随后先创建全部过孔，再创建全部直线。保留网络、层、坐标、线宽、锁定以及过孔类型、孔径、外径、盲埋孔规则名称、阻焊扩展；每个创建对象立即回读比较，再核对总数量。返回原图元编号与新图元编号对应表。公开创建接口分配新编号，不能保留原路线编号，也没有恢复隐藏分区／群组关联的创建参数。

当前仅支持两层铜箔板的直线和过孔。发现铜层圆弧或折线、多于两铜层、非法或缺失属性、元件／焊盘改变、目标已有路线时明确拒绝，不能静默丢弃圆弧，也不将其拆成直线。

创建失败或回读属性不符时立即报错，不再请求显式保存，不自动清理或回退。软件仍可能自动保存或在关闭时存盘；本次失败的原生路线副本在关闭后磁盘实际有497线和37过孔，因此失败隔离必须靠独立工程。显式保存必须返回`true`，随后调用公开设计规则检查（检查连接与间距等规则），其结果原样返回。保存成功仍需关闭自己会话后重开核实，并核对制造文件。

独立工程会改变工程内嵌库的归属编号。写回只在明确绑定源/目标工程且资源身份完全相等时映射外层库归属；真实元件资源身份为包含名称、来源、编号的对象，全部字段继续比较。第三方库不映射。

焊盘接口会把同一元件焊盘同时作为有关联父元件和无父元件的对象返回。本次快照433条焊盘记录包含这种重复，并非433个物理焊盘；实际已连接焊盘为160。两侧全部记录都核对，不能仅按编号粗略去重。
