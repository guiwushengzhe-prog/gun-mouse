# SuperMini 固件

当前为“固件3.2.1-摇杆与供电回报”，基于实机3.2增加摇杆开关、采样与中心、速度、体感灵敏度、陀螺仪就绪、命令执行序号及供电采样回报。保留原触摸逻辑、触摸门限、体感方向和设置存储格式；不包含试制3.3的装配与触摸方式改动。编译环境为官方3.3.12核心，128项固件电脑逻辑检查和8项蓝牙工具检查通过；`bin/`与`build-manifest.json`记录构建结果。实物部署另行记录，电脑检查不代表整机验收。

新增回报接口及充电识别边界见[状态回报与充电边界](状态回报与充电边界.md)。现有载板没有连接充电状态反馈线，因此回报采样电压并明确标记充电状态未知，不按电压推断正在充电或充满。

适配 **TENSTAR 两侧各 9 针、芯片标记 ESP32-S3FH4R2 的 ESP32-S3 SuperMini**：4MB Flash、2MB QSPI PSRAM；不要按某些商品文案的 8MB 或按 ESP32-C3 SuperMini 烧录。惯性模块为 GY-601N1 / LSM6DSV16X，3.3V 供电，I2C 地址 0x6A。IMU 中断脚不接，固件轮询。

触摸只控制体感移动，机械扳机/右键/摇杆按下分别为左/右/中键；摇杆不依赖触摸。松开触摸立即清除尚未发送的体感位移，断线不积累动作，重新连接且主机启用报告订阅后首帧全释放。按已认证的绑定客户端保存真实 CCCD 订阅；加密重连可以恢复该客户端的订阅，新配对不自动开订阅。GATT 拒绝通知时保留按键和位移队列重试；通知被栈接收不等于主机应用层确认。没有 Wi-Fi 功能。USB 原生 CDC 只用于烧录和串口设置，固件的鼠标行为不会因 USB 插拔暂停。

官方3.3.12核心在本机使用轻量蓝牙实现（NimBLE）。程序分别接入轻量实现的配对认证、报告订阅及连接间隔回调，并保留传统实现的处理；不能仅凭“已连接”判断鼠标可用，串口应同时显示“配对认证=通过”和“报告订阅=已启用”。传统实现中，认证完成前已收到的主机订阅请求优先于旧的保存值。

2026-10-24已在实板上观察到两次扳机按下、松开与Windows左键状态变化对应，用户确认左键可用；详见[蓝牙左键实测记录](实板上传记录/2026-10-24-蓝牙左键修复与实测.json)。这次验收只覆盖扳机左键，右键、触摸体感和电池供电仍需分别实测。首次上传记录对应历史提交6c8565c，当前构建文件与后续修复记录配套。

## 体感方向与握姿

2026-10-25用户反馈上下需要镜像，且惯性模块的轴向不一定等于实际握持的水平方向。旧实现将上下固定取芯片Z轴，竖直向量的XY分量长度降到0.6以下时，又将左右改为历史固定轴，会造成侧倾后串轴、水平动作减弱或方向突变。

当前实现参考[体感坐标映射与重力融合说明](https://gyrowiki.jibbsmart.com/blog:player-space-gyro-and-alternatives-explained)及其[原作者实现说明](https://github.com/JibbSmart/GamepadMotionHelpers)，自行在现有处理链中补齐以下计算，没有增加外部运行库：

- 用校正零偏后的陀螺仪角速度预测重力竖直方向，加速度计用于缓慢纠偏；明显偏离1倍重力的加速度不参与纠偏，陀螺仪预测继续运行。
- 左右角速度始终投影到当前竖直方向，取消侧倾时突然切回旧轴的分支。
- 上下角速度投影到“竖直方向与装配指向轴的叉乘”所确定的水平轴，再按本次要求相对旧版镜像。保留已存储的`invx`、`invy`附加反向设置，不重置蓝牙配对、触摸参数或摇杆停用状态。
- 装配指向轴沿用第二版正常竖握时芯片X向上、Z为俯仰轴的关系，取芯片Y轴；这补偿现有安装下的侧倾，不是自动识别任意新安装方向。指向接近竖直时，水平俯仰轴不能唯一确定，垂直输出平滑减弱，避免零向量归一化和突变。

检查覆盖正握、不同侧倾角、旧切轴边界、90度快速侧倾、附加线性加速度及接近指向竖直的边界。需在实物上以正常握持分别确认左右、上下和侧倾后的手感；算法不能仅凭重力知道用户任意定义的手部方向或屏幕朝向。开机约3秒静置校准与`cal`仍只负责零偏和初始重力，不是动作方向向导。

上述握姿补偿版本的上传和启动情况见[2026-10-25早先的体感方向上传记录](实板上传记录/2026-10-25-体感方向与握姿补偿.json)。用户随后确认上下合适，但左右的屏幕轨迹仍偏斜；后续改为在不旋转纯纵向轴的前提下扣除横向串轴。此前左键实测记录属于上一版的按键验收，不扩大为本轮方向验收。

## 蓝牙无线升级与屏幕轨迹校准

打开[蓝牙工具.ps1](蓝牙工具.ps1)，使用中文菜单查看状态、无线升级、校准左右或校准触摸。具体步骤、首次安装和分区说明见[蓝牙升级与校准.md](蓝牙升级与校准.md)。无需无线网络，使用已有加密绑定连接。

屏幕轨迹校准要求正常握持、实际触摸并左右小幅往返，电脑测量全局光标的方向后设置横向串轴系数；不要求用户估计角度。有效轨迹不足、只有单向动作或轨迹杂乱时保留原值。采样时其他鼠标保持不动，光标应留在同一屏幕内。原来的`hcal`还可直接按传感器输出采样6秒，作为串口校准入口，但其估计值不能直接当作屏幕轨迹的实测偏角。

触摸启动取最近32个样本的中位数和绝对偏差中位数，不再把最初的大读数累积进整段均值及噪声；按下确认6毫秒，松开仍即时清除触摸状态及待发送体感。用户本次实测正常握持未触摸约32788至32968，实际触摸约42107至43685，现有设备已保存触发8%、松开5%的设置。新的触摸校准菜单可针对实际装配重新测两组范围，不能把本次门限当作所有电极和握法的统一参数。

3.2版在触摸采样间隔超过20毫秒或读数失败时清除待确认状态；重新收到连续有效样本后仍按6毫秒确认，不把停顿时间算成持续触摸或持续低读数。惯性采样间隔超过10毫秒时，丢弃旧低通余量并跳过首个恢复样本；当前加速度可信时重新取得竖直方向，避免旧方向和旧移动延续到新样本。不改变正常连续采样下的方向公式、灵敏度或已保存校正值。

现有4兆闪存改用官方双应用分区。无线升级只写非运行应用分区，核对总长度、分包偏移和完整SHA256后才设置新启动分区。第一次从旧版迁移仍需要数据线安装分区表；本次保留设置区逐字节核对，并做过实际蓝牙传输及中止验证。详细运行及验收范围见`实板上传记录/2026-10-25-触摸左右校准与蓝牙升级.json`。

3.2版管理状态额外返回正在运行程序的构建校验值。电脑工具核对应用描述与飞鼠标识，更新后同时检查分区切换以及该构建校验值与发送文件一致；不能只看到版本号或分区变化就报告成功。应用描述格式依据[乐鑫官方应用镜像说明](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/system/app_image_format.html)，构建校验值与整个应用文件的SHA256分别记录，不混用。

## 引脚来源

`../pcb/carrier-config.json` 是载板与固件共同来源。运行 `python generate_board_pins.py` 生成 `gun_mouse_supermini/board_pins.h`，头文件记录整个配置的 SHA256，禁止手改。运行 `python generate_board_pins.py --check` 检查配置是否过期。

| 信号 | GPIO | 用途 |
| --- | ---: | --- |
| JOY_X / JOY_Y | 1 / 2 | ADC1，摇杆轴 |
| JOY_SW | 4 | 低电平有效，中键 |
| SDA / SCL | 5 / 6 | I2C，400kHz |
| TOUCH | 7 | ESP32-S3 原生触摸，触摸时计数上升 |
| TRIG | 8 | 低电平有效，左键 |
| VBAT_ADC | 9 | BAT_SW 经 100kΩ / 100kΩ + 100nF，电池隔离开关之后 |
| VBUS_DET | 10 | 保留旧引脚名称以兼容生成器；本版不连接、不采样 |
| BTN_R | 12 | 低电平有效，右键 |

GPIO3/45/46 启动配置脚不占用。19/20 是开发板内部原生 USB，载板不接。TX43/RX44 保留，本固件 `Serial` 使用原生 USB CDC。

## 电源行为及边界

本版取消外部供电识别和低电自动休眠，不再采样 GPIO10，也没有低电深睡、扳机唤醒或十分钟定时复查。插拔USB仍不暂停或恢复鼠标。

GPIO9 保留电池开关后的 **BAT_SW / SuperMini B+ 节点** 电压读取，电池电压约4秒平滑，蓝牙电量每分钟最多更新一次。只有电池开关打开时，该节点才代表电池端电压；电池开关关闭且USB供电时，空载充电器可能把它拉到约4.2伏，不能把读数当作电池已充满。

电量百分比只是电压估算。软件不再识别外部供电或充电状态，因此充电时不会暂停电量更新，估值可能偏高；串口状态也明确标注这个限制。电池仍需使用原定带保护板的单节锂电池。

右键和摇杆按键使用开发板内部上拉，保留原有按键消抖；扳机仍保留板外导线及外部上拉、滤波。鼠标按键、摇杆和触摸控制方式不变。固件不能改变开发板电源路径或USB回馈，这些仍按载板电源说明处理。

## 可复现编译

需要 Python 3.9+、[Arduino CLI](https://arduino.github.io/arduino-cli/latest/installation/) 和用于纯逻辑检查的 `g++`。官方 ESP32 Arduino 核心锁定为 **3.3.12**，所有 Arduino 库来自该核心，不需要第三方鼠标/IMU库。固件已适配该版本的 BLE 连接参数与 GAP 回调接口。

在仓库根目录运行（Linux、macOS、Windows PowerShell 均使用同一个 Python 脚本）：

```sh
python firmware/build_supermini_firmware.py --install-core
```

如果 Arduino CLI 不在 PATH，用 `--cli /path/to/arduino-cli` 或 Windows `--cli C:/Tools/arduino-cli.exe`。脚本默认在系统临时目录的英文路径建立独立 `data/downloads/user` 和缓存；可用 `--work-dir`、`--arduino-home` 改到自选路径。已有隔离 Arduino CLI 配置时用 `--config-file /path/to/arduino-cli.yaml`。代理环境用 `--proxy http://proxy-address:port`。不设置任何机器特定路径，不覆盖系统 HOME。

没有 g++ 时可以使用 `--skip-host-tests` 编译，交付清单会明确记录逻辑检查被跳过。本次交付的逻辑检查已执行。只检查逻辑：

```sh
python firmware/build_supermini_firmware.py --host-only
```

烧录参数在`build-config.json`：ESP32-S3开发板，4兆闪存、2兆四线扩展内存，默认双应用分区，每个应用区大小`0x140000`，160兆赫兹，原生硬件数据串口。启用原生数据串口的编译约束会避免误把串口配置成物理引脚串口。

成功编译后输出`bin/`下应用、引导、分区表和合并镜像，`build-manifest.json`记录校验值。合并镜像地址为`0x0`，用于匹配板型的全新安装；现有设备日常无线升级只发送应用文件，避免合并镜像中的空白填充覆盖设置。双分区设备不能不看当前启动分区就机械地只向`0x10000`更新。

## 首次烧录与验收

1. 首次烧录先断开电池，连接 SuperMini 自身 USB-C 数据线。在 Arduino IDE 按上面的参数选择板型并打开 `gun_mouse_supermini/gun_mouse_supermini.ino`，或用 Arduino CLI 编译后上传。若未枚举，按住 BOOT 再按 RESET，松开 BOOT 进入 ROM 下载模式；端口以实际枚举为准。

   手动进入下载模式后，原生串口的普通自动复位可能仍停留在下载模式。上传校验通过但没有程序回复时，可按复位键或使用烧录工具的 `--after watchdog-reset` 完成整机复位，再读取状态；参见[乐鑫官方排障说明](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/troubleshooting.html#leaving-download-mode-in-usb-serial-jtag-mode)。

2. 串口 115200 输入 `status`，确认摇杆中心、传感器 ID/校准和 BAT_SW 节点读数。电池开关关闭且USB供电时，B+可能读到空载充电器电压，不能把它当电池电量。静置约3秒完成体感校准，`cal`可重做。
3. 蓝牙搜索 **GunMouse SuperMini**。不触摸时晃动不会移动，但三键和摇杆仍可操作；触摸后体感移动，松开不会补发积压。重连后检查没有按键卡住。
4. 摇杆暂时拆除时，输入 `joy 0` 停用两路轴输入及中键，设置自动保存，重新上电仍保持停用。装回后让摇杆回中，输入 `joy 1` 恢复并取中；`jcenter` 重新取摇杆中位，`jdir` 按串口提示推向光标右、上方向，`jsave` 保存端点。原有参数重置命令不会改变这个独立保存的摇杆安装状态。装壳后用 `status` 看触摸读数，`tp <百分比>` / `tr <百分比>` 调整阈值，`sens <计数/度>` 调灵敏度。
5. 实板验证单电池、USB供电、插拔过渡、低电压无线峰值下的3.3伏电压、估算电量以及触摸抗误触。本次编译和电脑逻辑测试不代替这些实物检查。

Arduino CLI 上传示例（先用脚本完成编译；端口替换成实际 `/dev/ttyACM0` 或 `COM5`）：

```sh
arduino-cli upload --fqbn esp32:esp32:esp32s3:FlashSize=4M,PartitionScheme=default,FlashMode=qio,PSRAM=enabled,CDCOnBoot=cdc,USBMode=hwcdc,UploadSpeed=921600,CPUFreq=160 --port COM5 --input-dir firmware/bin firmware/gun_mouse_supermini
```

若编译使用独立工具链，上传同样加 `--config-file` 指向脚本生成的配置，否则命令可能找不到 ESP32 核心。

上述数据线上传示例只用于首次布置双分区；已经运行在另一应用分区的设备优先使用蓝牙工具，首次迁移与日常更新不能混为同一个写入步骤。
